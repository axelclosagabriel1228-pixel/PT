Part I: Introduction to Operating Systems

Platform Technologies

Platform Technologies are extensible hardware and software architectures that provide core services, abstraction layers, and interfaces that allow applications to be built and run.

Core system and infrastructure platforms

Operating System

An Operating System (OS) is the main software that runs a computer. It acts as a bridge between the user/application and the computer hardware.

Basic relationship

User/Application→ Operating System→ Hardware

Examples

  • Windows
  • macOS
  • Linux

Program

A single process can contain multiple threads.

Example: a quad-core CPU has 4 CPU cores.

Part III: Hardware Managed by the OS

CPU: Central Processing Unit

The processor that executes instructions and performs computations.

RAM: Random Access Memory

Memory used by programs and processes while they are running.

Exam clue

Temporary working memory used by active programs

Answer: RAM

Storage Devices

Used to store data. Examples: HDD, SSD.

Motherboard

The main circuit board connecting major computer components.

GPU: Graphics Processing Unit

Hardware designed primarily for graphics processing and parallel computations.

I/O Devices

Input/Output devices used to send data to the computer and receive data from the computer. Examples include keyboards, mice, printers, and other peripherals.

Part IV: OS as an Extended Machine

The OS acts as an Extended Machine by hiding complicated low-level hardware details and providing simpler ways for users and programs to interact with the computer.

Three important concepts

Hardware Abstraction
Hides complicated hardware details from users and applications.
Simplified Interaction
Provides easier ways for users and programs to interact with hardware.
Consistent APIs
Provides standardized interfaces that applications can use to request services.

Exam scenario

A programmer can use a standardized interface without directly handling the complicated details of the hardware.

Answer: OS as an Extended Machine / Consistent APIs

Part V: OS as a Resource Manager

The OS is also a Resource Manager. It fairly and efficiently manages resources such as the CPU and memory among competing programs.

Three important concepts

Controlled Allocation
Controls how resources are assigned to programs.
Time Multiplexing
Multiple processes share a resource by taking turns over time.
Space Multiplexing
A resource is divided into portions so multiple users/processes can use it.

Part VI: System Calls and Interrupts

System Call

A controlled interface through which a user-level program requests a service from the OS kernel.

Memory trick: Program requests OS service = SYSTEM CALL

Interrupt

A signal sent to the CPU telling it to temporarily pause its current work, handle an event, and then return to its previous work.

Memory trick: Interrupt = CPU is alerted to handle an event

Part VII: Five-State Process Model

A process moves through five primary states: New, Ready, Running, Waiting/Blocked, and Terminated.

The reviewer's memory diagram shows New, Ready, Running, then Waiting (back to Ready) or Terminated. The Running-to-Ready "preempted" arrow is added here because preemptive scheduling (SRTF, Round Robin) moves a running process back to the ready queue.

NEW

The process is being created.

Scenario

The OS is creating a newly launched application.

Answer: NEW

READY

The process is ready to run but waiting for CPU time. READY = waiting for CPU

RUNNING

The process is currently executing instructions using the CPU. RUNNING = using CPU

WAITING / BLOCKED

The process is waiting for an event or I/O operation to finish. WAITING = waiting for event/I/O

TERMINATED

The process has finished its execution.

Part VIII: CPU Scheduling

CPU Scheduling is the OS method of selecting processes from the ready queue and assigning them to the CPU.

Process Scheduling
The broader concept of deciding which process should execute.
CPU Scheduler
Also called the Short-Term Scheduler. It selects a process/thread from the ready queue to execute.
Ready Queue
A queue containing processes that are ready to execute and waiting for CPU time.

Part IX: CPU Scheduling Terminologies

CPU Burst
The period during which a process executes on the CPU.
I/O Burst
The period when a process performs or waits for an I/O operation.
Context Switch
Switching CPU execution from one process/thread to another.
Overhead
Context switch overhead: the CPU spends time performing the switch instead of executing application instructions.

During a context switch, the OS:

  1. Saves the state of the current process.
  2. Restores the state of another process.

Part X: Preemptive vs Non-Preemptive

Preemptive scheduling

The OS can interrupt a running process and give the CPU to another process.

Preemptive algorithms in scope: SRTF and Round Robin.

Non-preemptive scheduling

Once a process gets the CPU, it generally keeps it until it finishes or needs I/O.

Non-preemptive algorithms in scope: FCFS and SJB.

Part XI: Scheduling Policy vs Algorithm

Scheduling Policy
The general rule for deciding who should run.
Scheduling Algorithm
The specific procedure used to implement that decision.

Part XII: Four Core CPU Scheduling Formulas

Completion Time (CT)

The time at which a process finishes. On a Gantt chart, look at the right/end point of the process.

Turnaround Time (TAT)

Total time from arrival until completion.

TAT = CT - AT

CT is Completion Time and AT is Arrival Time.

Waiting Time (WT)

Total time spent waiting for the CPU.

WT = TAT - BT

TAT is Turnaround Time and BT is Burst Time.

Response Time (RT)

Time from arrival until the process first starts running.

RT = First Start Time - AT

Formula memory box

CT = time process finishes TAT = CT - AT WT = TAT - BT RT = First Start Time - AT

Part XIV: FCFS (First Come, First Served)

FCFS executes processes based on arrival order. It is non-preemptive.

WHO ARRIVES FIRST = RUNS FIRST

FIFO

FCFS uses First In, First Out. Processes enter at the tail and leave from the head.

Convoy Effect

Occurs when a CPU-bound process with a long CPU burst blocks multiple I/O-bound processes with short CPU bursts.

Exam clue

Long process is holding the CPU and many short processes are waiting.

Answer: CONVOY EFFECT

Part XV: SJB (Shortest Job First)

SJB selects the waiting process with the smallest CPU burst time. It is non-preemptive.

SHORTEST BURST = RUN FIRST

Once the shortest process starts running, it continues until it finishes or requests I/O.

SJB tie-breaker

If two processes have the same burst time, use FCFS order.

Part XVI: SRTF (Shortest Remaining Time First)

SRTF is the preemptive version of SJF. It selects the process with the smallest amount of remaining execution time.

SHORTEST REMAINING = RUN

Key difference

AlgorithmLooks at
SJBThe original burst time
SRTFThe remaining time

Part XVII: Round Robin

Round Robin is a preemptive CPU scheduling algorithm. Each process receives a fixed amount of CPU time called a time quantum. Processes take turns in cyclic order.

Time Quantum

A small fixed amount of CPU time assigned to each process. Typical range in the reviewer: 10 to 100 milliseconds.

Circular Queue

The ready queue operates like a FIFO ring, where processes repeatedly take turns until they finish.

P1 -> P2 -> P3 -> P1 -> P2 -> P3

Important RR rule

If a process finishes before its time quantum expires, it finishes and leaves the queue. The unused/excess quantum is not transferred to the next process.

Possible exam trap

TQ = 4. P1 only needs 2 units, so P1 uses 2. The remaining 2 units are not given to P2. P2 starts its own turn according to the queue.

Part XVIII: Extra Scheduling Concepts

These are not in the stated computation scope, but they are in the uploaded reviewer and may appear in identification or scenario questions.

Priority Scheduling

Each process is assigned a priority, and the scheduler selects processes according to priority.

Priority Number
A number assigned to a process to represent its priority.
Tie-breaker
If processes have the same priority: FCFS based on arrival order.
Static Priority
Priority remains fixed.
Dynamic Priority
Priority can be adjusted by the OS over time.
Starvation
A low-priority process may continue waiting because higher-priority processes keep arriving.
Aging
Gradually increases the priority of a waiting process.

Multilevel Feedback Queue

An advanced scheduling algorithm that allows processes to move dynamically among multiple ready queues based on CPU burst behavior.

Important concept: new processes enter the highest-priority queue.

Part XX: Types of Operating Systems

Batch OS
Processes jobs in batches without requiring continuous user interaction.
Multiprogramming
Allows multiple programs to stay in memory so the CPU can switch between them.
Multiprocessing
Uses multiple processors/CPU cores to execute work.
Multitasking OS
Allows multiple tasks/programs to appear to run at the same time by sharing CPU time.
Time-Sharing OS
Gives users/processes portions of CPU time so multiple tasks can interact with the system.
Distributed OS
Manages multiple connected computers and makes them work together as a system.
Network OS
Provides services for computers connected through a network.
Real-Time OS
Designed to respond to events within specific timing requirements.

Then follow:

  1. Determine execution order.
  2. Draw the Gantt chart.
  3. Get CT from the ending point.
  4. Calculate TAT = CT - AT.
  5. Calculate WT = TAT - BT.
  6. Calculate RT = First Start Time - AT.
  7. Calculate averages.
